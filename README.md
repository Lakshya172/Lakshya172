01 · EligiCore
Universal eligibility and assisted-application platform for students
EligiCore is designed to help students understand which opportunities may fit their profiles. The platform direction includes a reusable student profile, resume parsing, job ingestion through source adapters, eligibility and matching logic, and a human checkpoint before final submission.
Engineering focus
- Separating job ingestion, normalization, eligibility, and recommendation concerns.
- Using a consistent job schema and deduplication strategy for incoming records.
- Keeping matching outcomes explicit, including cases where an opportunity is no longer open or a student is not eligible.
- Designing AI-provider boundaries so the application is not tied to a single provider.
- Emphasizing automated tests and repeatable checks as the project evolves.
- Keeping final application submission under human control where websites impose anti-bot or other restrictions.
Stack: Python · REST/API design · data modelling · AI-provider integration · automated testing

How I approach engineering
A feature is not finished just because the happy path works.

- Make the rules explicit. Business logic should be understandable and testable rather than hidden in scattered conditionals.
- Treat edge cases as part of the design. Missing data, duplicate records, invalid states, and unavailable resources deserve deliberate behaviour.
- Keep responsibilities separated. APIs, data access, matching rules, and user interfaces should have clear boundaries.
- Test behaviour, not just execution. A passing response is not enough if the resulting state is wrong.
- Document important decisions. Future contributors should be able to understand not only what changed, but why.
These are principles I’m practising as I build and improve my projects.
